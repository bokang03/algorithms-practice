# [Programmers] 최솟값 만들기 (Level 2) - 문제 설명

## 1. 개요
* **출처:** 프로그래머스 (Lv. 2)
* **권장 풀이 시간:** 15분
* **핵심 키워드:** 그리디(Greedy), 정렬(Sorting), 배열(Array)

---

## 2. 문제 설명
길이가 같은 두 개의 배열 `A`와 `B`가 주어집니다. 배열 `A`, `B`에서 각각 한 개의 숫자를 뽑아 두 수를 곱합니다. 이러한 과정을 배열의 길이만큼 반복하며, 두 수를 곱한 결과를 누적하여 더합니다.

이때, **최종적으로 누적된 값이 최소가 되도록** 만드는 것이 목표입니다. (단, 각 배열에서 k번째 숫자를 뽑았다면 다음에 그 K번째 숫자는 다시 뽑을 수 없습니다.)

---

## 3. 해결 전략 (그리디 알고리즘)
곱의 누적합을 최소로 만들기 위해서는 **한 배열의 가장 큰 값과 다른 배열의 가장 작은 값을 곱하는 것**이 최선의 선택입니다.

1. 배열 `A`는 **오름차순**으로 정렬합니다. (가장 작은 값부터 순서대로)
2. 배열 `B`는 **내림차순**으로 정렬합니다. (가장 큰 값부터 순서대로)
3. 두 배열의 같은 인덱스 요소끼리 곱한 뒤 누적합을 구합니다.

---

## 4. 제한 사항
* 배열 `A`, `B`의 크기: 1,000 이하의 자연수
* 배열 `A`, `B`의 원소의 크기: 1,000 이하의 자연수

---

## 5. 입출력 예시

| A | B | answer |
| :--- | :--- | :--- |
| `[1, 4, 2]` | `[5, 4, 4]` | **29** |
| `[1, 2]` | `[3, 4]` | **10** |

### 입출력 예 설명

* **첫 번째 예시 (`A = [1, 4, 2], B = [5, 4, 4]`)**
  * `A`를 오름차순 정렬: `[1, 2, 4]`
  * `B`를 내림차순 정렬: `[5, 4, 4]`
  * 곱의 합: $(1 \times 5) + (2 \times 4) + (4 \times 4) = 5 + 8 + 16 = \mathbf{29}$

* **두 번째 예시 (`A = [1, 2], B = [3, 4]`)**
  * `A`를 오름차순 정렬: `[1, 2]`
  * `B`를 내림차순 정렬: `[4, 3]`
  * 곱의 합: $(1 \times 4) + (2 \times 3) = 4 + 6 = \mathbf{10}$
